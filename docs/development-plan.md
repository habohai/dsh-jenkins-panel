# dsh-jenkins-panel 开发计划

> 基线：`0.2.0-rc.1`，当前 `main` 已包含右侧栏面板、触发记录、失败分析与构建完成通知。
> 本文记录“已实现 / 待实现 / 明确不做”，避免重复讨论和误实现。

## 当前状态

已完成：

- 右侧栏「Jenkins面板」页签，和「会话信息 / 任务」同属官方右侧栏；
- 总览/任务/构建详情、日志、产物、工作空间；
- 多连接、凭据服务、设置页/插件页连接配置；
- 触发记录注册表（持久化、TTL、并发去重）；
- 失败自动分析（只读任务书）；
- 构建完成主动通知（默认成功，失败走 analysis）；
- 同会话 2 秒内完成合并；
- `triggerId` / `queueUrl` / 脱敏参数返回；
- 排队超过 30 秒的 `build_started`；
- 完成通知带 `triggerId`、版本、耗时、URL、失败阶段；
- 失败分析可建议重试，但只有用户明确要求才执行，禁止自动连续重试。

## P2（未实现）

### 1. 通知投递重试

**只重发通知消息，绝不重跑构建。**

- 使用 `triggerId` 幂等；
- 有限次数 + 退避；
- 失败状态 `failed` 可观测；
- 禁止在重试路径调用 `jenkins_build_trigger` / `jenkins_build_retry`。

### 2. Session 离线补投

- 当前：`skipped` + 日志；
- 目标：持久化 pending，session 下次活跃时补发；
- 必须处理重复投递和重启恢复。

### 3. 排队位置 / 原因通知

- 当前 trigger 返回 `queueUrl`；
- 可选：排队超过阈值后带队列位置/`why`；
- 默认不频繁唤醒模型。

### 4. 多构建批量策略

- 当前 2 秒内完成合并；
- 更长窗口/“等全部完成再通知”需要显式策略，不能默认等待全部，避免长构建阻塞。

### 5. 通知配置 UI

- `notifications.*` 目前只能改配置 YAML / 插件配置；
- 目标：插件页/设置卡片暴露启用、成功、取消、开始阈值、debounce；
- 与 `analysis.enabled` 同源。

## 其他已知缺口

- **Jenkins CSRF crumb 未处理**：开启 CSRF 的实例上 POST 可能 403；
- **手动构建不跟踪**：只通知插件触发的记录；
- **失败摘要不落通知**：只给 `failureStage`，日志由模型调用 `jenkins_build_log`；
- **插件 host 日志无模型工具**：模型可读 Jenkins 构建日志，但读不到插件内部 host 日志；
- **无真实端到端构建验证**：当前覆盖单测，尚未在真实 Jenkins 上跑完整通知链路。

## 里程碑

1. **M1（当前）**：右侧栏 UI、触发/通知闭环；
2. **M2**：通知配置 UI + 真实构建 E2E；
3. **M3**：通知投递重试 + 离线补投；
4. **M4**：排队位置/原因与可观测性。

## 设计约束

- 触发恒不等待；
- 构建失败不自动重试；
- 通知投递重试 ≠ 构建重试；
- 参数响应/通知必须脱敏；
- 失败分析只读查日志，重试需用户明确要求；
- 通知默认只回 DSH Session；
- 同一构建只通知一次，通知带 `triggerId` / `buildNumber`。
